DIFFERENT TECHNIQUES. DIFFERENT JOBS.

What changes?
What stays in the model?

01 / INITIAL TRAINING

Pretraining

Creates a model’s initial learned capabilities from training data. Frontier foundation-model pretraining is not our positioning; we primarily work with existing models and frameworks.

02 / WEIGHT ADAPTATION

Fine-tuning

Updates model weights using a training dataset for a task or domain. LoRA and QLoRA are parameter-efficient approaches. This needs suitable data, evaluation and an explicit training plan.

03 / RETRIEVED CONTEXT

RAG

Finds relevant information from approved sources and supplies it to the model at runtime. Adding documents to an index does not retrain the model. Source permissions and relevance still need testing.

04 / INSTRUCTIONS

Prompting

Gives a model instructions and examples at request time. It can guide behavior without updating weights. A prompt alone does not enforce authorization or transaction rules.

05 / EXPLICIT INTERFACES

Runtime tools

Let the application handle structured model requests through APIs or business functions. Code checks the arguments, caller permissions and action policy before anything sensitive happens.

06 / MEASURED PATTERNS

Conventional ML

Predicts, classifies or detects patterns using task-specific data. Statistical models and deterministic rules can solve a problem without a conversational interface.

DEPLOYMENT CHOICES

Where should it run?

Choose based on data sensitivity, task quality, hardware, budget and who will operate the system.

01

Hosted model API

A provider operates a proprietary or open model behind an external service. Requests leave your environment for processing under that provider’s applicable terms and configuration.

Assess retention, location, contractual requirements, availability, cost and the information sent.

02

Local or private inference

Run an appropriately licensed open-weight model on customer-controlled hardware or private infrastructure. You take responsibility for capacity, updates, network controls and operation.

Local inference can reduce external processing. It does not by itself prove privacy or compliance.

03

Hybrid architecture

Use local and external components for different tasks under explicit routing policies. Define what may leave the environment and what must stay within it.

Check embeddings, retrieval, telemetry, backups and every fallback path, as well as the main model.

EVALUATION, SECURITY & GOVERNANCE

Trust needs
engineering evidence.

Evaluate the actual task.

Golden datasets, retrieval checks, regression tests and human review. A model judge is useful only with calibration and known limitations.

Enforce boundaries in code.

Test prompt injection, tool authorization and tenant isolation. Validate arguments and protect transactions with explicit approval and retry rules.

Observe and investigate.

Track costs, latency, outcomes and appropriate audit evidence. Investigate incidents and use feedback to prioritize improvements.

Release changes deliberately.

Version models, prompts and interfaces. Evaluation informs a reviewed release; it does not automatically modify production weights.

Controls and responsibilities are assessed for each deployment. No blanket certification, compliance or complete-privacy promise is made.
